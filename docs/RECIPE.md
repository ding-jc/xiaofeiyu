> **来源声明**：本文档基于上游仓库
> [PC2005-cloud/dsh-pet · MAKE-YOUR-OWN-PET.md](https://github.com/PC2005-cloud/dsh-pet/blob/main/MAKE-YOUR-OWN-PET.md)
> 整理改写；提示词库保留原文语义，目录结构、字段、校验规则与安装方式已按本仓库的
> **xiaofeiyu-asset-v1** 格式重写。
>
> 面向本仓库的 **xiaofeiyu-asset-v1** 格式：从一段提示词到可导入的素材包。
> 字段与校验规则以《[素材资产格式规范](../素材资产格式规范.md)》为准，本文只讲"怎么做出合格的素材"。
> 三段式：**① 提示词生成绿幕视频 → ② 抠像与转码 → ③ 写 config.json 并安装**。

---

## 总览

| 阶段 | 输入 | 输出 | 工具 |
|---|---|---|---|
| ① 提示词 | 角色设定 | 10 秒绿幕 MP4 | 视频生成模型（可灵 / Runway / 豆包等） |
| ② 处理 | 绿幕 MP4 | 640×360 透明 WebM | Python + ffmpeg + numpy/scipy |
| ③ 打包 | WebM + config.json | 可导入素材包（目录或 zip） | 本 app「添加角色」 |

> 官方素材链全部采用 PR 手工抠像路线；自动 HSV 抠像保留为兜底，可一键生成但含复杂透明边缘时易残边。

## ① 提示词配方

### 1.1 通用前缀（每段视频必带，直接粘贴）

```
【绝对空间与边界约束强制命令】
视频比例 16:9，背景必须为纯粹的绿幕色（标准 Chroma Key Green，颜色严格统一为 #00FF00），
无任何阴影、杂物、渐变或边框，背景本身即为单一纯色块。
【人物位置与大小强制固定】角色必须完完全全处于画面正中心偏下位置：头顶始终处于画面垂直方向约
20% 的位置，脚底始终处于约 85% 的位置，最左和最右边缘始终处于水平方向约 25% 和 75% 的位置。
不同视频之间的人物大小、位置、比例必须完全一致，不允许有任何偏差。
【画幅安全红线】全库安全缓冲统一为画幅任意一边的 10%。动作全程任何一帧，角色任何身体部位
（呆毛、耳鳍、裙摆、尾巴、手脚指尖）以及所有道具与特效对象，最外点都必须与对应边缘保持 ≥10%
画幅宽/高的间距；绝对禁止接触、超出或被裁剪。动作全程必须在画幅内部完成。
【绝对居中锚点】双脚落点坐标恒定为画面正中央，全程不允许产生 X 轴或 Y 轴平移位移
（仅允许轴心旋转、原地跳跃、脚尖原地点地）。无论道具多大，角色与对象的组合视觉重心必须始终
保持在画面水平正中；严禁为容纳道具而把角色向左右移动、向后移动或靠向边缘。
【大物件构图规则】物件高度＞画幅 30% 时，必须位于角色正前方/正上方/环绕轴线，与角色共用画面
水平中心线；放不下就 Q 版缩小以整体入画，绝不移动人物来腾空间；角色与物件必须同框。
【"无→有→无"道具闭环】含道具/特效的视频：入场第一帧必须是标准正面站立、画面干净无任何道具；
道具由角色以魔法手势从无到有渐进凝聚生成（先半透明虚影，0.5~1 秒凝实），绝不直接出现在首帧；
结束前 0.5~1 秒由实到虚渐次消散，尾帧回到无道具的标准正面站立。任何一帧不得凭空出现道具。
【侧身互动 ≠ 构图横移】需要侧身面向物件时，一律原地轴心转动上身/头部或脚尖原地点地转向，
双脚与原点始终静止；"退后、后移、走到一侧、挪到旁边"等位移描述一律改写为原地轴转。
所有视频必须以标准正面图为第一起始帧（画面干净、无道具），并在第 10 秒结束时彻底恢复到与
第一帧完全一致、无道具残留的标准正面站立姿态。不同视频之间绿幕色值必须完全一致。
```

### 1.2 动作提示词（替换【动作描述】批量产出）

采用「动作概述 + 按秒分割画面」两段式，官方原文范例：

```
待机呼吸休闲
动作概述：Q版角色原地站立，身体自然有节奏轻微上下起伏（呼吸感），双眼平视前方，每隔
  3-5 秒轻快眨眼一次；头顶呆毛与身后尾巴极其微小舒缓地左右摆动。无位移，无切边，
  全身结构完整保留在画面中央。
按秒分割画面：
- 0~3秒：身体极轻微上下起伏模拟呼吸，每隔约 2 秒眨眼一次，双臂自然垂放。
- 3~7秒：头部极小幅度向左、向右缓慢转动，仿佛环顾四周，呆毛随之柔顺摆动，重心始终原位。
- 7~10秒：头部缓缓回正，呼吸恢复平稳。第 10 秒结束时与首帧标准正面站立完全一致。
```

| 分类 | 动作概述（接在通用前缀之后） | 首尾帧要求 |
|---|---|---|
| idle 待机 | 原地站立、轻微呼吸起伏、自然眨眼、呆毛/尾巴微摆。 | 首帧=尾帧=标准正面站立 |
| turn 转向 | 东张西望：先向左张望再向右转，原地轴转不位移。 | **例外**：尾帧为起始帧的严格左右镜像，不回正 |
| move 移动 | 原地漂浮踏步 / 螃蟹走路 / 原地左转奔跑，脚下无实际平移。 | 首尾站立 |
| click 点击回应 | 开心跃动 / 害羞惊讶 / 傲娇生气 / 被吓一跳，短促反应。 | 首尾站立 |
| drag 拖拽 | 被无形的手提起悬空，四肢自然下垂放松，表情略带惊讶。 | 悬空姿势保持 |
| random 随机 | 伸懒腰 / 悠闲哼歌 / 玩魔方 / 吃白饭 / 写代码 / 中秋赏月。 | 首尾站立 |

> 官方 `turn` 的「东张西望」要求第 9~10 秒定格为起始帧的几何镜像（可顺带产出右侧基准图），
> 与大多数动作「回正站立」相反，制作时务必区别对待。

### 1.3 睡觉三段（接力，首尾必须能无缝衔接）

```
入睡（start）：【角色】从站立姿势缓缓打哈欠、揉眼睛，逐渐坐下/趴下变为睡姿。
  首帧必须站立，尾帧必须是睡姿。全程禁止中途起身。
循环（loop）：【角色】保持睡姿安静睡觉，轻微呼吸起伏，偶尔翻身。
  关键：首帧与尾帧必须逐帧完全相同，才能无缝循环。Zzz 图形须在段末完全淡出。
醒来（end）：【角色】从睡姿缓缓睁眼、伸腰，站起身来。
  首帧必须是睡姿，尾帧必须是站立。
```

> 三段共用同一条地面线、同一角色大小；生成后先比对「入睡尾帧 = 循环首帧 = 醒来首帧」
> 与「醒来尾帧 = 入睡首帧」一致后再入链。配置里 `animations.sleep` 一套 = start / loop / end 三个候选数组。

## ② 抠像与转码

### 2.1 处理链（两条路线二选一）

```sh
video/<动作名>.mp4                  源视频（10 秒绿幕，中文名 mp4）
  → watermark_step01.py           水印遮罩填充 → step01/
  → chroma_step02.py              绿幕抠像转透明（HSV 自动）→ step02/
  → （路线 B）PR 手工抠像 .mov 覆盖 → pr_import_step02.py → step02/
  → normalize_step03.py           2160×1215 母版统一站立居中 → step03/
  → encode_thumbs.py              640×360 播放变体 → step04/
  → videos/<分类>/<动作名>.webm   成品
```

两条路线产出同一级 `step02/`，后续步骤完全一致。依赖：Python 3 + ffmpeg + numpy + scipy。

> 路线 A（默认）：`chroma_step02.py` 自动 HSV 抠像，人人可复现；路线 B（官方采用）：PR 手工抠像导出
> 带 alpha 的 ProRes 4444 `.mov` 放 `pr/`，文件名与动作名一致，覆盖自动结果。

### 2.2 成品规格（硬性）

| 项 | 值 |
|---|---|
| 分辨率 | 640×360（16:9），母版 2160×1215 |
| 编码 | VP9 + alpha 通道 |
| 帧率 | 24fps |
| 音轨 | 无（-an） |
| 脚底对齐 | y=330（母版 1215 画布脚底约 1115） |
| 透明校验 | 首帧 A 通道 max>200 且 min<100 |

> Safari 兼容：另导出 HEVC-with-alpha 的 `.mov`。dsh 插件放 `<root>-animation/mov/`；
> 本格式放 `videos-mov/<分类>/` 同名对应，缺失时自动回退 `.webm`。

### 2.3 关键 ffmpeg 参数

```bash
# 母版归一化（保留 alpha：显式解码 + yuva420p）
ffmpeg -i input.mov -c:v libvpx-vp9 -vf "scale=2160:1215,format=yuva420p" -crf 30 -b:v 0 -r 24 out.webm
# 播放变体
ffmpeg -i master.webm -vf "scale=640:360,format=yuva420p" -crf 40 -b:v 0 -row-mt 1 -r 24 -an final.webm
```

## ③ 编写 config.json 并安装

### 3.1 目录结构

```
<角色id>/
├─ config.json             唯一清单
├─ videos/<分类>/*.webm    主素材（idle/turn/move/click/drag/random/events）
├─ videos-mov/<分类>/*.mov Safari 素材（可选）
├─ sounds/click.wav        点击音效（可选，随包携带便于导出 dsh）
└─ recipe.md               本配方
```

### 3.2 导入器会检查什么（打包前先对照）

| 规则 | 值 |
|---|---|
| 视频扩展名 | `webm / mp4 / m4v / mov / gif / apng / png / webp`，其它扩展名不算素材 |
| 分类目录 | 只认 `videos/{idle,turn,idle_turn,move,click,drag,random,events}`，未知目录落 `random` |
| 角色 id | 建议纯小写字母数字；含中文会自动转义并追加哈希后缀（长度上限 48） |
| ZIP 包 | ≤ 4096 个条目、解压后 ≤ 800 MB；同名包**不会覆盖**，会装成 `-1` |
| 点击音效 | 缺 `sounds/click.wav` 时，自动拿源里（按路径排序）第一份 `.wav` 顶上 |
| `idle_turn` | 自动复制进 `idle` 与 `turn` 两个池 |

### 3.3 config.json 最小模板（复制后改）

```json
{
  "format": "xiaofeiyu-asset-v1",
  "id": "mycat",
  "name": "我的猫",
  "theme": "#e8974a",
  "canvas": [640, 360],
  "scale": 0.72,
  "bodyBox": [200, 50, 440, 335],
  "headBox": [200, 50, 440, 167],
  "noMirror": ["写代码", "写福字"],
  "actions": {
    "idle":   ["videos/idle/待机呼吸.webm"],
    "turn":   ["videos/turn/东张西望.webm"],
    "click":  ["videos/click/点击回应-开心跃动.webm"],
    "drag":   ["videos/drag/被拖拽悬空.webm"],
    "move":   ["videos/move/漂浮踏步.webm"],
    "random": ["videos/random/吃饭.webm"]
  },
  "media": { "formats": ["webm", "mov"], "safariDir": "videos-mov" },
  "fps": 24,
  "feetY": 330,
  "recipe": "recipe.md"
}
```

要点：

- `id` 只用小写字母数字最省事；中文名会自动转义并加哈希后缀（可读性差但不撞名）。
- `bodyBox` / `headBox` 是相对 640×360 画布的命中区，直接决定"点到哪算点到角色"。
- `noMirror`：含可读文字的动画名填这里，避免转向镜像后文字反显（子串匹配）。
- `persona` / `audio` / `prompt` 在本 app 里只是元数据（本 app 无对话能力、音效由应用设置控制），
  写上是为了导出 dsh 插件时不丢信息——详见规范 §2.1 的"运行时"列。

### 3.4 安装

- **文件夹**：主界面「添加角色」→ 选素材包文件夹（内含 `config.json`）。
- **zip**：把整个 `<角色id>/` 打成 zip，直接拖进主界面窗口。
- **dsh 素材包**：`config.jsonc`（Web 原版）或 `character.json` + `videos/`（桌面版）都能直接导入，
  导入时自动识别并转成本格式，原文件全量保留。
- **导出回 dsh**：角色卡片「导出 dsh」得 zip，「写入 dsh」直接落到 `~/.dsh/dsh-pet/pet/`。

## 校验清单

- [ ] 每段视频 640×360 / VP9 alpha / 24fps / 无音轨，绿幕色值全库一致为 #00FF00
- [ ] 全身与道具最外点与画幅边缘保持 ≥10% 安全区，首帧无道具、尾帧回正（turn 镜像例外）
- [ ] 睡觉循环段首尾逐帧相同，「入睡尾帧 = 循环首帧 = 醒来首帧」
- [ ] 含文字动画已列入 noMirror
- [ ] config.json 的 actions 路径与实际文件一一对应（对不上会静默丢动作）
- [ ] 目录名只用分类白名单，未知目录的视频会落进 random
- [ ] ZIP 条目 ≤4096、解压后 ≤800 MB，否则导入器直接拒绝
- [ ] 素材来源写进 `source`（MIT 合规）

## 常见问题

**Q：视频放进去但角色不动？**
先看 `config.json` 的 `actions` 里有没有登记这个文件——没登记的不会播；再确认分类目录名在
白名单里（`videos/myidle/` 这种会落进 random）。

**Q：透明边缘有绿边/黑边？**
抠像残留。用 `despill` 或换 PR 手工抠像路线（配方 ②.1 的路线 B）。

**Q：想加一段"被点两下"的动作？**
放进 `videos/click/` 即可，同分类多段会随机取一；不需要改清单（除非用 `actions` 显式声明）。

**Q：能不能直接用 dsh 的完整分件包？**
可以。官方 `core + extra1..6` 解压后目录结构本身就是桌面版布局，直接「添加角色」选那个目录，
导入器会合并识别。
